# Blog 用户与默认权限

身份与授权由 Blog 数据库管理，与 UAA 登录身份映射分开。默认身份字段为
`user.is_admin`，角色关联为 `sys_user_role`。已有 `ROLE_ADMIN` 身份与
`is_admin = 1` 在整理时统一，避免界面和接口对管理员身份判断不同。

| 用户 | 默认能力 | 数据库表示 |
| --- | --- | --- |
| 游客 | 浏览公开文章、音乐、项目、留言及友链等公开功能 | 无需创建游客账号 |
| 普通登录用户 | 与游客相同的公开功能，不因登录自动获得受保护的业务能力 | `is_admin = 0`，`ROLE_USER` 无业务权限关联 |
| 管理员 | 所有模块能力，包括模块内后续新增权限 | `is_admin = 1`，关联 `ROLE_ADMIN`；角色仅关联各模块的 `XXX:*` |
| 额外授权用户 | 公开功能加管理员显式授予的能力 | 保留普通身份，在 `sys_user_permission` 中单独授权 |

聊天仍需登录。普通用户只有同时获得 `chat:read` 和 `chat:send` 后才能聊天；
只授予 `chat:read` 时可以查看聊天但不能发言。AI、文章编辑、系统配置等能力
也需要对应权限。管理员无需逐项授权。

管理员不重复关联 `article:create` 等明细权限，也不额外缓存全局 `*`；
`article:*`、`chat:*` 等模块通配符覆盖相应模块的明细操作。

`ROLE_USER` 是保留的默认身份角色，不用于统一授予额外能力。单独授权通过
现有权限管理界面进行；自定义角色和已有用户单独授权在默认权限整理中保留。

启动时 `BlogPermissionInitializer` 在事务中同步权限清单与说明、补齐管理员
权限、修复默认角色关联、清空 `ROLE_USER` 的业务权限，并清除用户权限缓存。
创建新用户时同时写入相应角色关联。

已有数据库可以先备份权限表和用户身份字段，再重启 Blog，由
`BlogPermissionInitializer` 完成默认权限整理及相应用户权限缓存清理。
